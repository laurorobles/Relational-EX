# Relational EX — Design Principles

## 1. Every control explains itself

Every interactive control must provide English hover help. Descriptions should explain cause and effect, not merely define the name.

## 2. No dead space

Margins and spacing are structural. Empty space should improve hierarchy, readability or interaction. Decorative voids are not a design goal.

## 3. Modules are bounded systems

Every functional area is visually contained within a frame. Module boundaries explain where one relationship ends and another begins.

## 4. Data is the visual language

Frequency positions, spectral density, event probability and cyclic relationships should be visualized from real state values rather than decorative animation.

## 5. One model, multiple views

The sequencer's Field, Grid and Radial views must always represent the same underlying event data.

## 6. Experimental, not retro cosplay

The visual character should feel like a precision instrument from an unfamiliar laboratory: dark, compact, geometric and analytical, while avoiding a literal imitation of any specific historical hardware.

## 7. Musical control over randomness

Randomness must have a bounded, inspectable parameter and predictable statistical behavior. “Chaos” is not an excuse for unrepeatable UI behavior.

## 8. Audio thread purity

No network, disk browsing or UI logic inside realtime audio processing.
